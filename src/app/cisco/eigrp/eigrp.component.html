EIGRP Enhanced interior Gateway Routing Protocol

Characteristics
- is a distance vector routing protocol
- derivative of Interior Gateway Routing Protocol (IGRP) but includes support for variable length subnet masking (VLSM) and metrics capable of supporting higher-speed interfaces.
- overcomes the deficiencies: with features such as unequal-cost load balancing, support for networks 255 hops away, and rapid convergence features.
- uses a diffusing update algorithm (DUAL) to identify network paths and provides for fast convergence using precalculated loop-free backup paths.
- advertise incremental updates only as topology changes occur within a network. main concepts
Successor route: The route with the lowest path metric to reach a destination
Successor: The first next-hop router for the successor route.
Feasible distance (FD): The metric value for the lowest-metric path to reach a destination. (lo que me cuesta llegar)
Reported distance: (RD): Distance reported by a router to reach a prefix (el valor que reporta el next-hop)
Feasibility condition: For a route to be considered a backup route, the RD received for that route must be less than the FD calculated locally RD < FD
Feasible successor: A route with that satisfies the feasibility condition is maintained as a backup route. The feasibility condition ensures that the backup route is loop free.

Inter-Router Communication

five different packet types
Hello -> Used for discovery of EIGRP neighbors and for detecting when a neighbor is no longer available
Request -> Used to get specific information from one or more neighbors
Update -> Used to transmit routing and reachability information with other EIGRP neighbors
Query -> Sent out to search for another path during convergence
Reply- > Sent in response to a query packet
- uses its own IP protocol number (88) and uses multicast packets where possible; it uses unicast packets when necessary.
- Communication between routers is done with multicast using the group address 224.0.0.10 or the MAC address 01:00:5e:00:00:0a
- EIGRP uses multicast packets to reduce bandwidth consumed on a link (one packet to reach multiple devices).
- Reliable Transport Protocol (RTP) to ensure that packets are delivered in order and to ensure that routers receive specific packets. A sequence number is included in each EIGRP packet. The sequence value zero does not require a response from the receiving EIGRP router; all other values require an ACK packet that includes the original sequence number.

Forming EIGRP Neighbors

The following parameters must match for the two routers to become neighbors:
• Metric formula K values
• Primary subnet matches
• Autonomous system number (ASN) matches
• Authentication parameters

Process EIGRP uses for forming neighbor adjacencies

1 Hello / (both)
2 Update packet (Unicast) with Init Set / (beginner)
3 ACK / (receiver)

4 Update packet (Unicast) routes sent / (beginner)
5 ACK / (receiver)

6 Update Packet (Unicast) End of Table / (beginner)
7 ACK (receiver)
Use the show ip eigrp neighbors command to verify EIGRP neighbors The output lists:
- the IPv4 address of the neighboring device’s interface that sent the hello packet
- the local interface on the router used to reach that neighbor
- how long the local router will consider the neighboring router to be a neighbor
- how long the routers have been neighbors
- the amount of time it takes for the neighbors to communicate
- the number of EIGRP packets in a queue waiting to be sent to a neighbor
- a sequence number to keep track of the EIGRP packets to ensure that only newer packets from the neighbor are accepted and processed
When you use the network command, the EIGRP process is enabled on the interfaces that fall within the range of IP addresses identified by the command
You can confirm which interfaces are participating in the EIGRP process by using the show ip eigrp interfaces

EIGRP Configuration Modes

two methods of EIGRP configuration are classic mode and named mode.

Classic Configuration Mode

- Classic EIGRP :most of the configuration takes place in the EIGRP process, but some settings are configured under the interface configuration submode. Some of the settings that are set individually are hello advertisement interval, split-horizon, authentication, and summary route advertisements.

command

named mode configuration

Provides the following benefits:
- All the EIGRP configuration occurs in one location.
- Supports current EIGRP features and future developments.
- It supports multiple address families (including Virtual Routing and Forwarding [VRF] instances).
- Named mode provides a hierarchical configuration and stores settings in three subsections
- Address Family: contains settings that are relevant to the global EIGRP AS operations, such as selection of network interfaces, EIGRP K values, logging settings, and stub settings
- Interface: submode contains settings such as hello advertisement interval, split-horizon, authentication, and summary route advertisements. Commands can be assigned to a specific interface or to a default interface, in which case those settings are placed on all EIGRP-enabled interfaces. If there is a conflict between the default interface and a specific interface, the specific interface takes priority over the default interface
- Topology: contains settings regarding the EIGRP topology database and how routes are presented to the router’s RIB. This section also contains route redistribution and administrative distance settings.

Path Metric Calculations

K values to define which factors the formula uses and the impact associated with a factor when calculating the metric. BW represents the slowest link in the path, scaled to a 10 Gbps link (107). Link speed is collected from the configured interface bandwidth on an interface. Delay is the total measure of delay in the path, measured in tens of microseconds
The EIGRP formula is based on the IGRP metric formula, except the output is multiplied by 256 to change the metric from 24 bits to 32 bits
By default, K1 and K3 have a value of 1, and K2, K4, and K5 are set to 0.
The EIGRP path attributes can include hop count, cumulative delay, minimum bandwidth link speed, and RD.

Load Balancing

allows multiple successor routes (with the same metric) to be installed for the same prefix, is called equal-cost multipathing (ECMP) routing. The default maximum ECMP is four routes. You change the default ECMP setting with the command maximum-paths under the EIGRP process in classic mode and under the topology base submode in named mode.
EIGRP supports unequal-cost load balancing, which allows installation of both successor routes and feasible successors into the EIGRP RIB.
To use unequal-cost load balancing with EIGRP, change EIGRP’s variance multiplier. The EIGRP variance value is the feasible distance (FD) for a route multiplied by the EIGRP variance multiplier. Any feasible successor’s FD with a metric below the EIGRP variance value is installed into the RIB.
EIGRP hello packets are sent out in intervals according to the hello timer. The hold timer is the amount of time EIGRP deems the router reachable and functioning. The hold time value defaults to three times the hello interval. The hold time decrements, and upon receipt of a hello packet, the hold time resets and restarts the countdown. If the hold time reaches 0, EIGRP declares the neighbor unreachable and notifies the diffusing update algorithm (DUAL) of a topology change.
classic configuration mode the interface command ip hello-interval eigrp as-number seconds, and the hold timer is modified with the command ip hold-time eigrp as-number seconds. hello and hold timers are verified by viewing the EIGRP interfaces with the command show ip eigrp interfaces detail

EIGRP Query Packets

If a feasible successor is not available for the prefix, DUAL must perform a new route. The route state changes from passive (P) to active (A) in the EIGRP topology table.
The router detecting the topology change sends out query packets to EIGRP neighbors for the route. Upon receipt of a query packet, an EIGRP router does one of the following.
- It replies to the query that the router does not have a route to the prefix.
- If the query came from the successor for the route, the receiving router detects the delay set for infinity, sets the prefix as active in the EIGRP topology, and sends out a query packet to all downstream EIGRP neighbors for that route.
A router receives an EIGRP query packet, that query happens to come from the neighbor (successor) to reach a certain network. Inside that query, "I no longer have a valid path — my metric to this network is infinite." This is announcing the route just died on its end. The router's best path just disappeared, it has to formally mark that route as Active in its topology table, meaning "I'm now actively searching for a new best path.".
To find a new path, the router asks all of its other EIGRP neighbors (except the one): "Do you have a route to this network? What's your distance to it?"
- If the query did not come from the successor for that route, it detects that the delay is set for infinity but ignores it because it did not come from the successor. The receiving router replies with the EIGRP attributes for that route. Instead of going Active and launching its own query, the router answers with its known route information (its distance/metric to that destination) — saying: "Here's my valid path to that network, in case it helps you."
The query process continues from router to router until a router establishes the query boundary. query boundary is established when a router does not mark the prefix as active, meaning
- It says it does not have a route to the prefix. ( it has nothing to contribute either way, it just replies "unreachable" and the query goes no further in that direction)
- It replies with EIGRP attributes because the query did not come from the successor. (It just answers back with its route info (a normal Reply packet))

EIGRP Convergence Topology

A router loses its successor → goes Active → queries everyone downstream. Each of those neighbors either hits a query boundary (replies immediately) or also goes Active and queries further outward.
This keeps expanding outward until it hits boundaries everywhere.
Then it reverses: each router, once all its own outstanding queries are answered, goes Passive and replies to whoever queried it.
This "unwinding" ripples backward, hop by hop, until the original router — the one where the failure was first detected — gets all its replies back, goes Passive, and DUAL is fully converged.

Stuck in Active

EIGRP maintains a timer called “active timer” which has a default value of 3 minutes (180 seconds). EIGRP waits half of the active timer value (90 seconds) for a reply. If the router does not receive a response within 90 seconds, the originating router sends a stuck in active (SIA) query to EIGRP neighbors that did not respond
Upon receipt of an SIA query, the router should respond within 90 seconds with an SIA reply. An SIA reply contains the route information or provides information on the query process itself.
If a router fails to respond to an SIA query by the time the active timer expires, EIGRP deems the router SIA. DUAL deletes all routes from that neighbor, the situation is as if the neighbor responded with unreachable for all routes.
If a router fails to respond to an SIA query by the time the active timer expires, EIGRP deems the router SIA. If the SIA state is declared for a neighbor, DUAL deletes all routes from that neighbor, treating the situation as if the neighbor responded with unreachable message for all routes.
You show active queries with the command show ip eigrp topology.

Configuration of SIA Timers

the active timer can be disabled or modified with the command timers active-time {disabled | 1-65535-minutes} under the EIGRP process. with named mode configuration, the command runs under the topology base.

Route Summarization

EIGRP Hierarchical Summarization

route summarization (shrinking the routing table of all the routers) creates a query boundary, shrinks the query domain when route goes active during convergence, reducing SIA scenarios

Interface-Specific Summarization

EIGRP summarizes network prefixes on an interface-by-interface basis
A summary aggregate is configured for the EIGRP interface. (You manually configure a summary route directly on that specific interface)
The summary aggregate prefix is not advertised until a prefix matches it. (The summary route doesn't get advertised unless the router already has at least one route in its topology table that actually falls within that summary range.)
Interface-specific summarization can be performed in any portion of the network topology. (You can configure a summary on literally any EIGRP-speaking interface, anywhere in the topology — core, distribution, access layer, WAN links, etc.)
classic EIGRP configuration mode, you use the interface parameter command ip summary address eigrp as-number network subnet-mask [leak-map route-map-name] to place an EIGRP summary aggregate on an interface
named mode under the af-interface interface-id, use the command summary-address network subnet-mask [leak-map route-map-name].

Summary Discard Routes

EIGRP installs a discard route on the summarizing routers as a routing loop prevention mechanism
is a route that matches the summary aggregate prefix with the destination Null0. This prevents routing loops where portions of the summarized network range do not have a more specific entry in the Routing Information Base (RIB) on the summarizing router. The AD for the Null0 route is 5 by default

EIGRP Summarization Metrics

the summary inherits the metric of whichever component route has the best (lowest) metric.
fluctuation in the path metric is resolved by statically setting the metric on the summary aggregate with the command summary-metric network {/prefix-length | subnet-mask} bandwidth delay reliability load MTU

EIGRP Stub Router

An EIGRP stub router does not advertise routes that it learns from other EIGRP peers.
EIGRP stubs advertise only connected and summary routes, but they can be configured so that they only receive routes or advertise any combination of redistributed routes, connected routes, or summary routes.
The EIGRP stub router announces itself as a stub within the EIGRP hello packet If a route goes active, EIGRP does not send EIGRP queries to an EIGRP stub router.
You configure a stub router by placing the command eigrp stub {connected | receive-only | redistributed | static | summary} under the EIGRP process for classic configuration and under the address family for named mode configuration.
EIGRP neighbors on WAN links do not send EIGRP queries to the remote site when a route becomes active.
The EIGRP stub site feature allows downstream routers to receive and advertise network prefixes across the WAN.
The EIGRP stub site feature prevents the EIGRP stub site route from being a transit site. Stub Site lets you apply stub behavior selectively, per interface — specifically on WAN interfaces
EIGRP neighbors on WAN links do not send EIGRP queries to the remote site when a route becomes active.
The EIGRP stub site feature allows downstream routers to receive and advertise network prefixes across the WAN.
The EIGRP stub site feature prevents the EIGRP stub site route from being a transit site

EIGRP Stub Site Config

stub site function is available only in EIGRP named mode configuration.
The WAN interfaces are identified underneath the af-interface interface-id hierarchy and use the stub-site wan-interface command.
The stub site function and identifier are enabled with the command eigrp stub-site as-number:identifier.

Split Horizon

Split horizon prevents the advertisement of reverse routes EIGRP enables split horizon on all interfaces by default.
Disable split horizon on a specific interface by using the interface parameter command no ip split-horizon eigrp as-number with EIGRP classic configuration.
Disable split horizon on EIGRP named mode configuration under the af-interface default or af-interface interface-id, using the command no split-horizon.

Route Manipulation

Route Filtering

EIGRP supports filtering of routes as they are received or advertised from an interface.
Filtering of routes can be matched against:
Access control lists (ACLs) (named or numbered)
IP prefix lists
Route maps
Gateway IP addresses
inbound filtering drops routes prior to the DUAL processing, not installe on RIB.
outbound filtering, the routes are processed by DUAL and are installed into the local RIB

EIGRP Distribution List Filtering

Filtering is accomplished with the command distribute-list {acl-number | acl-name | prefix prefix-list-name | route-map route-map-name | gateway prefix-list-name} {in | out} [interface-id].
EIGRP classic configuration places the command under the EIGRP process, while named mode configuration places the command under the topology base.
Prefixes that match against deny statements are filtered, and prefixes that match against a permit are passed.

Traffic Steering with EIGRP Offset Lists

Offset lists allow for the modification of route attributes based on the direction of the update
An offset list is configured with the command offset-list offset-value {acl-number | acl-name] {in | out} [interface-id] to modify the metric value of a route
